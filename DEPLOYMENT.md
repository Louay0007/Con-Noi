# Deployment

Two supported targets. Pick one.

- **Option A — Docker Compose (recommended):** one command brings up Mongo, the API and the web app.
- **Option B — Manual VPS:** Node 24 + MongoDB installed directly, systemd units.

---

## Option A — Docker Compose

### 1. Prerequisites
- Docker Engine 24+ with the Compose plugin
- A server with at least 2 GB RAM (Mongo + API + Caddy)
- A domain pointed at the server (optional but required for HTTPS)

### 2. Configure the backend
```sh
cd backend
cp .env.example .env
node scripts/gen-secrets.js      # writes strong JWT secrets into .env
```

Then edit `backend/.env` and set at minimum:

| Variable | What to put |
| --- | --- |
| `FRONTEND_URL` | Your public URL, e.g. `https://app.example.com` |
| `SEED_ADMIN_EMAIL` | The first admin login |
| `SEED_ADMIN_PASSWORD` | A strong password (change after first login) |

`MONGO_URI` is overridden by Compose — leave it as-is.

> The API **refuses to boot** if `JWT_*_SECRET` is under 32 characters. That is intentional.

### 3. Build and start
```sh
docker compose up -d --build
docker compose ps          # all services should report healthy
```

### 4. Seed the first admin + demo catalogue
```sh
docker compose exec api node -e "require('./dist/modules/seed/seed.js')"
```
Or, if you want only the admin:
```sh
docker compose exec api npm run seed
```

### 5. Verify
```sh
curl http://localhost:8080/api/v1/health
# {"data":{"status":"ok","database":"connected",...}}
```
Open `http://SERVER_IP:8080` — the landing page and `/auth/login` should render.

### 6. Put it behind HTTPS
The `web` container publishes `8080`. Terminate TLS in front of it with Caddy,
nginx or your cloud load balancer, forwarding to `127.0.0.1:8080`.

Minimal Caddy on the host (`/etc/caddy/Caddyfile`):
```
app.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Then set `FRONTEND_URL=https://app.example.com` in `backend/.env` and
`docker compose up -d api` to reload CORS.

## Option B — Manual VPS

### 1. Install runtime
```sh
# Node 24
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt install -y nodejs
# MongoDB 7
sudo apt install -y mongodb-org
sudo systemctl enable --now mongod
```

### 2. Backend
```sh
cd backend
cp .env.example .env
node scripts/gen-secrets.js
npm ci
npm run build
npm run seed
NODE_ENV=production node dist/main.js
```

Put it under systemd (`/etc/systemd/system/con-noi-api.service`):
```ini
[Unit]
Description=Con-Noi API
After=network.target mongod.service

[Service]
Type=simple
User=connoi
WorkingDirectory=/srv/con-noi/backend
EnvironmentFile=/srv/con-noi/backend/.env
ExecStart=/usr/bin/node dist/main.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
```sh
sudo systemctl enable --now con-noi-api
```

### 3. Frontend
```sh
cd frontend
npm ci
npm run build
```
Serve `frontend/dist` with nginx and proxy `/api` to `127.0.0.1:4000`:

```nginx
server {
    listen 80;
    server_name app.example.com;
    root /srv/con-noi/frontend/dist;

    location /api/ {
        proxy_pass http://127.0.0.1:4000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        try_files $uri =404;
    }

    location / {
        try_files $uri /index.html;
    }
}
```

## Environment reference

| Variable | Required | Notes |
| --- | --- | --- |
| `MONGO_URI` | yes | Compose overrides this to the `mongo` service |
| `JWT_ACCESS_SECRET` | yes | ≥ 32 chars, generated by the script |
| `JWT_REFRESH_SECRET` | yes | ≥ 32 chars, must differ from the access secret |
| `FRONTEND_URL` | yes | Comma-separated allowed origins |
| `PORT` | no | Default `4000` |
| `STORAGE_DRIVER` | no | `disk` (default) or `s3` |
| `STORAGE_DIR` | no | Default `./uploads`; mount a volume |
| `THROTTLE_LIMIT` | no | Requests per window, default `100` |
| `SEED_ADMIN_*` | no | Used only by the seed script |

## Operations

**Backups** — Mongo data lives in the `mongo-data` volume:
```sh
docker compose exec mongo mongodump --archive --gzip > backup-$(date +%F).gz
```

**Logs**
```sh
docker compose logs -f api
```

**Upgrades**
```sh
git pull
docker compose up -d --build
```

**Health endpoint** — `GET /api/v1/health` returns `status` and `database`.
Both Compose services have healthchecks wired to it.

## Production checklist

- [ ] `backend/.env` has 32+ char JWT secrets (not the example values)
- [ ] `FRONTEND_URL` matches the real domain
- [ ] `SEED_ADMIN_PASSWORD` changed after first login
- [ ] HTTPS terminated in front of `web:8080`
- [ ] `uploads` volume backed up if `STORAGE_DRIVER=disk`
- [ ] Mongo volume backed up on a schedule
- [ ] Swagger is disabled automatically when `NODE_ENV=production`
- [ ] `docker compose ps` shows every service `healthy`

## Known limitations before selling

Read this before quoting a customer:

1. **No email delivery.** Password reset and email verification are not
   implemented. The reset screen shows a neutral confirmation and does
   nothing. This needs an SMTP/SES provider wired into `auth`.
2. **Disk storage is single-instance.** With `STORAGE_DRIVER=disk`, uploads
   live on one container. Use S3 before scaling to more than one API replica.
3. **Virus scanning is simulated.** Files upload as `pending` and the cron
   marks them `clean`. Wire ClamAV before accepting untrusted public uploads.
4. **No payment or billing module.** There is no subscription handling.
5. **Frontend route table is inconsistent.** `src/lib/routes.ts` still
   describes an older product; `App.tsx` is the source of truth today.
